LogTriage 로컬 설치형 (Windows) 사용법
=====================================

■ LogTriage.exe  ← 기본 프로그램 (GUI)
  더블클릭하면 분석기 화면이 열립니다.
  [로그분석] → 로그 파일 선택(제품 자동 감지) → 장애 시각 입력
  → [즉시 분석 시작] → 분석 리포트 확인.
  분석 이력은 대시보드에 자동 저장됩니다.
  룰팩(.rpk) 적용도 [룰팩 업데이트] 메뉴에서 클릭으로 가능합니다.

■ logtriage-cli.exe  ← 명령줄 도구 (자동화·스크립트용)
  logtriage-cli.exe 파일 --product tomcat --incident-time "2026-09-02 14:05"
  logtriage-cli.exe --incident-time "2026-09-02 14:05" ^
     --input C:\logs\catalina.out:tomcat:was01 ^
     --input C:\logs\alert_orcl.log:oracle:db01
  파일을 logtriage-cli.exe 위로 드래그하면 대화형으로도 실행됩니다.

■ 룰 폴더
  rules\        : 룰팩으로 갱신되는 시그니처 룰 (직접 수정 금지)
  rules-local\  : 사이트 커스텀 룰 (룰팩 갱신 영향 없음, ID 충돌 시 우선)

■ 실행이 차단될 때
  Windows SmartScreen 경고가 뜨면 [추가 정보] → [실행] 을 누르세요.
  (코드서명 인증서 적용 전까지 나타날 수 있습니다)

■ 다른 PC·다른 사람에게 줄 때 (2026-10-22 개정 — 받은 사람은 아무 설정 없이 실행)
  배포 묶음 LogTriage-PC-1.0.0.zip(반출 폴더) 을 주십시오 — exe 둘과 안내 글만 들어 있습니다(이 PC 의 분석 이력·계정·설정은 담지 않음).
  판정 지식(룰·코드·매뉴얼·보고서 서식)은 exe 안에 들어 있어 처음 실행할 때 저절로 펼칩니다. 받은 사람은 다음 중 어느 것이든 됩니다:
  - 압축을 풀어 아무 폴더(바탕화면·D:\ 등)에서 실행 → 자료(이력·보고서·설정)를 exe 옆에 둡니다.
  - 압축 안에서 바로 실행(탐색기·반디집·알집·7-Zip·WinRAR) 또는 Program Files·읽기 전용 USB 같은 쓸 수 없는 폴더에서 실행
    → 자료를 그 사용자 자리 %LOCALAPPDATA%\LogTriage\home 에 둡니다(화면 위 파란 'ℹ 알림'으로 위치를 알려 줌 — 고칠 것 없음).
    같은 PC 의 다른 계정은 각자 자기 자리를 씁니다. 새 판 exe 로 바꾸면 그 자리의 옛 내장 지식은 backups 로 옮기고 새로 펼칩니다.
  - Microsoft Edge WebView2 런타임이 없는 PC(일부 LTSC·오래된 Windows) → 같은 화면을 기본 웹 브라우저로 엽니다.
    안내 창의 [확인]이 '끝내기' 입니다. 파일은 끌어 놓기 대신 [파일 선택](올리기)으로 넣습니다. WebView2 를 설치하면 다음부터 창으로 열립니다.
  ※ 설치 폴더(dist)나 빌드 폴더를 통째로 남에게 주지 마십시오 — 이 PC 의 자료(data·incidents·conf·backups)가 함께 갑니다.
  ※ 내 PC 를 옮길 때(같은 사람)는 설치 폴더째 복사하면 이력까지 옮겨지고, 경고 없이 이어집니다.

■ 실시간 관제 · 자원 사용률 수집 설정 (2026-10-22 추가)
  [모니터링] 위 [📡 실시간 관제] (주소 /nms/live) — 관제실 모니터용 전체 화면. 감시 항목을 등록하면 저절로 움직입니다.
  - 위: 감시 항목·정상·주의·장애·활성 알림·평균 응답(최근 1분), 값 옆 막대는 최근 30번의 변화. 장애가 있으면 장애 칸이 빨갛게 깜빡입니다.
  - 가용률: 반원 게이지(정상 / 판정한 항목) + 정상 비율·주의 비율·최근 10분 검사 실패율.
  - 응답 시간 분포: 최근 10분 모든 검사를 점으로(위로 갈수록 느림, 맨 위 띠는 실패). 마우스로 끌어 영역을 고르면 그 검사들이 목록으로 나옵니다.
    점에 올리면 서버·시각·응답, [전체 서버]로 한 서버만 볼 수 있습니다.
  - 이벤트: 장애 발생·복구·임계치 초과가 맨 위로 쌓입니다(종류별로 고를 수 있음).
  - 서버 이퀄라이저: 서버마다 CPU·메모리·디스크 막대(C·M·D), 임계치에 가까우면 주황·넘으면 빨강.
  - CPU 추이: 최근 10분 상위 5대, 마우스를 올리면 그 시각의 값.
  - 새로고침 2·5·10초, 일시정지, 전체 화면(관제실 TV), [감시 항목으로].
  자원 사용률 수집 설정 — 항목마다 수집 방식과 주기를 바로 바꿉니다(가용성 상태·장애 이력은 그대로).
  - 실시간 관제 [⚙ 수집 설정]: 항목별 수집 방식(안 함·이 서버 자체·에이전트·SNMP)·주기(기본·5초·10초·30초·1분·5분)·최근 값·[지금 갱신]·[전체 지금 갱신].
  - [모니터링] 항목을 고르고 [자원 사용률] 탭: 수집 주기·[지금 갱신]. 수집하지 않는 항목이면 단추 한 번으로 수집을 켭니다.
  - 기본 주기: 이 서버 자체 10초, 에이전트·SNMP 30초. SNMP 는 장비 부하를 생각해 10초보다 짧게 하지 않습니다.
  - [지금 갱신]: 이 서버 자체·SNMP 는 바로 수집합니다. 에이전트는 원격 서버가 보내는 값이라 다음 보고 때 반영됩니다.
  - 에이전트(lt-agent.py)는 서버 화면에서 정한 주기를 응답으로 받아 다음 전송부터 따릅니다(옛 에이전트·셸·PowerShell 에이전트는 실행할 때 준 주기 그대로).
  - SNMP 로 바꾸려면 커뮤니티가 필요합니다 — 감시 항목 [편집]에서 넣으십시오(수집 설정 화면에서는 비밀값을 받지 않습니다).
  - [📡 실시간 관제 ↗]는 새 창으로 열립니다(프로그램 창이면 새 프로그램 창, 브라우저면 새 창 — 로그인 상태가 이어짐). 관제 창의 [감시 항목으로]는 원래 창으로 돌아갑니다.
  - 응답 시간만 나오고 자원 사용률이 안 나오면: ① 수집 방식이 '수집 안 함'인지 ② '에이전트'인데 대상 서버에 에이전트가 없는지
    ③ 에이전트 보고가 거절되는지 보십시오. ③은 [모니터링] 위 노란 띠·관제 [⚙ 수집 설정] 위에 '보낸 곳·호스트명·이유·고치는 법'이 나옵니다
    (토큰이 틀린 요청은 '출처 확인 안 됨'으로 표시). 고쳐서 보고가 들어오면 안내는 사라집니다.
  - 에이전트(lt-agent.sh)는 전송 실패 때 실제 이유(curl 오류 문구)를 로그에 남기고, 설치(lt-agent-install.sh) 때 실제 전송을 한 번 시험하며,
    같은 서버에 에이전트가 겹쳐 돌면 목록과 끄는 법을 보여 줍니다. 로그에 '[HTTP 000] … 서버에 닿지 못했습니다'가 나오면
    중간 방화벽·보안 장비가 대상 서버 → LogTriage 서버 포트의 POST 를 막는 경우가 많습니다(보안 담당에 예외 요청).
  - 알아 둘 점: 감시 항목 [편집] 창을 열어 둔 채 다른 화면에서 수집 방식·주기를 바꾸고 [편집] 창을 저장하면, 편집 창에 처음 불러온 값이 마지막으로 저장됩니다(마지막 저장 우선). 편집 창은 저장 직전에 다시 열어 쓰십시오.

■ 현장 의견 반영 (2026-10-22 — 실제 사용자 피드백)
  · 로그 올리기: 오른쪽 아래 카드에 진행률·속도·경과·남은 시간. 다 보낸 뒤 서버가 받는 동안은 '서버에 저장하는 중', 서버가 받았다고 답해야 '올리기 완료'.
  · 장애 보고서: 작성 중 경과 초 → 끝나면 초록 '작성 완료' 카드와 큰 내려받기 단추. 나중에 다시 받으려면 [예약·자동화 › 산출물 · 내려받기](서버형).
  · 판정 리포트 [📋 요약 글 복사](옛 이름 '1장 요약 복사'): 메신저·메일에 붙여 넣을 요약 글을 복사하고, 복사한 글을 화면에 그대로 보여 줍니다. 파일은 만들지 않습니다.
  · 판정 근거: 기본 '요약'(같은 판정끼리 묶어 등급·횟수·처음→마지막), [전체 목록]으로 줄마다. 묶음 안 가장 심각한 줄이 대표, 등급·서버·코드가 섞이면 '외 N'.
  · 같은 부서 공유: 계정의 부서가 같으면 다른 사람이 한 분석도 원본·보고서를 씁니다. 직접 가입 때 적은 부서는 관리자가 [사용자 · 권한] 편집 창에서
    [신청 부서 확인]을 체크하거나 부서를 직접 정한 뒤부터 공유됩니다(가입 승인만으로는 확인되지 않음, 목록에 '신청 부서·확인 전').
  · 모니터링: 목록에는 포트 번호를 보이지 않습니다('TCP · 30초마다'). 상세에서 ●●●●● [보기]를 눌러야 보이며, 자산 권한이 없는 계정은 서버가 포트 값을 아예 보내지 않습니다.
  · 자산 관리: '자산 목록 파일 미리 점검'(옛 '우리 기준으로 읽어 보기'), '점검 항목 설정'(옛 '기준 손보기').
  · 자산 보기 수량: 제목 행의 NO·번호·순번·연번 열을 찾아 번호가 있는 줄만 '데이터 N건'으로 셉니다. 합계·※비고·빈 병합 줄은 '번호 없는 줄'로 따로 세고
    노란 바탕으로 표시합니다([번호 없는 줄만 보기]). 번호 열이 없는 시트는 예전처럼 줄 수입니다. 위쪽 '표 전체 N줄'은 제목·합계까지 포함한 값입니다.
  · 예약 작업 표에 '등록일시' 칸. 이 기능 이전에 등록한 작업은 '기록 없음'(시각을 지어내지 않습니다).
  · 예약·자동화 › 저장 경로: '업로드 원본 로그' 줄에 [7일 지난 것/30일 지난 것/전부 ▼][🗑 삭제] — 관리자만. 화면에서 올린 원본만 지우며
    반입 폴더(inbox)는 건드리지 않습니다. 지난 분석의 판정·원문 미리보기·로그 검색은 그대로 남습니다. 분석·백업 중에는 거절합니다. 누가 몇 개 지웠는지 알림함·감사 기록에 남습니다.
  · 관리 › 사용자 · 권한: '시연 자료' 탭을 없앴습니다(홈의 30초 체험은 그대로).
  · 실시간 관제 이퀄라이저: 서버마다 한 줄 가로 막대, 임계치에 가장 가까운 서버가 위로.
  · 실시간 관제 가용률(2차 의견): 예전에는 '지금 정상인 항목 비율'이라 지금 장애가 없으면 늘 100% 였습니다. 이제 **최근 24시간 항목별 검사 성공률의 평균**입니다
    (시간 가용률·SLA 값이 아님). 눈금은 90~100, 가장 낮은 항목을 함께 보여 주고, 유효한 검사가 없는 항목은 '측정 불가'(평균 제외)·수집 오류가 많은 항목은 경고로 따로 알립니다.
    지금 상태 비율은 아래 '정상 비율' 도넛입니다.
  · 판정 리포트: 계정으로 로그인하는 서버에서는 처음 열 때 **내가 올린 분석**이 나오고, 제목 아래 [분석 선택]에서 '내 분석 / 다른 사용자 분석(등록자)'을 골라 봅니다.
    다른 부서 분석은 예전처럼 가린 값으로 보입니다. 머리에 '등록 나 / 이름'.
  · 문구: 판정 리포트 카드 '무슨 일이 일어났나 → 발생 현상', '판단 근거 → 판정 요지', '하지 말 것 → 1차 대응 금지 사항', 홈 '지금 할 일 → 우선 확인 사항',
    '분석 완료', '견본 로그로 체험', 코드 '뜻 → 의미'. 안내문 말끝은 '~하십시오'로 통일(단추·탭은 짧은 이름 그대로).
  · 전체 현황 숫자 카드: 값 크기를 22px 로 고정(큰 화면에서 제목보다 커지던 문제), '분석 완료 · 치명 포함 분석 · 최다 최초 관측 계층(계층은 알약) · 평균 분석 소요 시간'.
  · 모니터링 응답 시간 추이: 아래 긴 설명 줄을 없애고 위에 색 범례(응답 시간 · 실패 · 수집 오류) + 요약 수치 한 줄. 화면 맨 아래 안내도 한 문단으로.
  · 예약·자동화 표 아래 안내 한 줄, 자산 미리 점검 ⚠ 줄의 설명(마우스를 올리면)을 쉬운 두 문장으로.
  · 간결한 화면(3차 의견): 화면마다 맨 위 부제를 한 줄 이름으로 줄였습니다. 긴 안내문(90자 이상)은 한 줄만 보이고 오른쪽 끝 [ⓘ 자세히]로 펼칩니다
    (글은 지우지 않음 · 인쇄할 때는 펼쳐짐 · 다시 그려도 펼친 상태 유지). 단 위험·주의·삭제·복구 불가·비밀번호·토큰·외부 전송 같은 안내,
    오류·상태 알림, 빈 화면 안내, 표 안 글, 단추·입력이 든 글은 접지 않고 늘 보입니다.
  · 로그인 첫 화면(4차 의견 '글이 많고 그림으로 기능이 떠오르지 않는다'): 제목 한 줄 + 기능 아이콘 4개(장애 판정 · 실시간 관제 · 보고서 자동 작성 · 부서 공유)
    + '로그 → 판정 → 관제·보고서' 흐름 그림만 남겼습니다. 저장 방식·잠금 횟수는 마우스를 올리면 보이고, 틀리면 오류 줄에 남은 시도 횟수가 나옵니다.

■ 서버 모드 — 윈도우 PC 에서 다른 서버의 모니터링 정보 수집(리눅스 설치형과 같은 역할) (2026-09-17)
  1) LogTriage.exe 옆의 server.conf.example 을 server.conf 로 복사하고 PASSWORD 를 정합니다(LISTEN=0.0.0.0, PORT=8088).
     PASSWORD 는 10자 이상이어야 하고 예시 값('바꾸세요')은 받지 않습니다 — 아니면 창 모드는 이 PC 안에서만 열고, 상시 모드는 띄우지 않습니다(2026-10-26).
  2) 두 가지 방법 중 하나:
     - 창 모드: 그냥 LogTriage.exe 를 실행 — server.conf 가 있으면 창이 열린 채로 0.0.0.0:8088 에서 에이전트 푸시·브라우저 접속을 받습니다(창을 닫으면 멈춤).
     - 상시 모드: LogTriage-server.cmd start — 창 없이 서버만 돕니다. stop / status / log / enable-boot(로그온 시 자동 시작) / disable-boot.
  3) 방화벽: 다른 서버가 이 PC 로 보내려면 인바운드 TCP 8088 허용이 필요 — 관리자 콘솔에서 LogTriage-server.cmd firewall
  4) 리눅스 서버 쪽: 브라우저로 http://<이 PC IP>:8088/ 에 로그인 → [모니터링] → [+ 감시 항목 등록] → 자원 사용률 수집 '에이전트' → [⬇ lt-agent.zip 받기]
     → 그 서버에서 unzip lt-agent.zip && cd lt-agent && sh lt-agent-ctl.sh start  (root 불필요, zip 안에 이 PC 주소·토큰 포함)
     대상 서버가 이 PC 화면에서 직접 받을 수 없으면(망 분리 등): 이 PC 의 LogTriage 창 → [모니터링] → 항목 [편집] → 에이전트
       → '이 대상 전용 토큰으로 내려받기' 칸의 [⬇ lt-agent.zip] 으로 받아 USB 등으로 옮긴 뒤 같은 명령으로 실행합니다(Windows 서버는 lt-agent.cmd start).
       USB 로 옮길 때: 이 zip 의 agent.conf 에 그 대상 전용 토큰이 들어 있어 열쇠와 같습니다 — 설치 뒤 USB · 내려받은 PC 의 zip 을 지우고,
       잃어버렸거나 다른 사람 손을 거쳤으면 같은 화면의 토큰 목록에서 그 토큰을 [폐기]한 뒤 새로 받으십시오.
     PC 묶음의 agent 폴더는 같은 수집기 원본입니다(주소·토큰 없음 — 설치 전 내용 검토용). 수집 토큰은 화면·명령줄에 나오지 않고
     내려받은 파일(agent.conf, 권한 600)에만 들어가므로, 실행에는 위에서 받은 zip 을 쓰십시오.
  * exe 창 자체는 같은 PC 라 로그인 없이 열리고, LAN 에서 오는 브라우저 접속만 비밀번호를 묻습니다. PASSWORD 가 없으면 LAN 수신을 하지 않습니다(127.0.0.1 로만).
  * PASSWORD 는 10자 이상, 추측하기 어려운 값이어야 합니다(예시 값 · 숫자만 · 같은 글자 반복 · admin2026 처럼 흔한 낱말+숫자 · qwerty 같은 키보드 연속은 거부).
    창 모드에서 거부되면 이 PC 안에서만 열리고, 화면 위 '환경 점검' 띠에 '에이전트 수집이 들어오지 않음'이 창을 닫을 때까지 남습니다.
  * 서버 모드와 창 모드는 같은 데이터 폴더를 쓰므로 동시에 하나만 뜹니다. 서버 모드가 떠 있을 때 exe 를 더블클릭하면 브라우저로 그 화면을 엽니다.
  * 로그: logtriage_server.log, pid: server.pid (exe 옆)
  * 보안: LAN 은 HTTP 평문(사내망 기준). server.conf 는 다른 계정이 읽지 못하게(cmd start 가 권한 제한 시도). exe 는 쓰기 가능한 폴더에. exe 창은 프로세스만 아는 부트스트랩 토큰으로 세션을 얻고 같은 PC 의 다른 사용자도 로그인해야 합니다.
