로그인 연동 방법 — conf/auth.json

      사내 인증 시스템이 제공하는 방식 하나를 고릅니다. 모두 추가 설치 없이 동작합니다. 파일을 고친 뒤 서비스를 다시 시작하십시오. 비밀값은 화면에 표시하지 않습니다.

      ① ldap — 디렉터리(AD/LDAP) 계정: 로그인 화면에서 계정 ID·비밀번호 입력 → 디렉터리에 바로 확인(LDAPS 권장). 부서·그룹으로 권한 자동 부여 가능.

      ② oidc — OpenID Connect(Keycloak 등) 제공 시: [통합 로그인(SSO)] 버튼 → 로그인 → 돌아옴. 서명(RS256)·발급자·만료 검증.

      ③ header — SSO 에이전트가 붙은 앞단 웹서버(nginx/Apache)가 사용자 ID 를 헤더로 전달. 이 서버는 127.0.0.1 로만 열고 앞단만 접속하게 하십시오.

      ④ link — 메뉴 링크에 사용자·시각·서명(HMAC-SHA256)을 붙여 이동. 2분 유효, 한 번만 사용.

      통합 로그인 장애 대비 비상용 로컬 관리자: python -m logtriage.auth --base /opt/logtriage set-admin (Windows: LogTriage.exe --auth-admin set-admin) → /login?local=1

      

  
남은 임시 백업 폴더 

    
백업 중 프로그램이 강제로 끝나면 자료 사본이 든 .backup-… 폴더가 남습니다.
      주인이 끝난 폴더는 다음 백업 때 자동으로 지우며 여기서 바로 지울 수도 있습니다. 주인 표식이 없는 폴더(예전 판이 만든 것)는
      먼저 격리(이름 바꾸기)하고 10분 뒤 그사이 아무것도 쓰지 않았을 때만 지우기가 됩니다. 백업이 돌고 있거나, 10분 안에 바뀐 파일이 있거나,
      안의 파일을 무언가 열고 있거나, 안에 링크·정션이 있거나, 백업 묶음을 쓰는 중이면 하지 않습니다. 한 일은 감사 기록에 남습니다.

    
 일
      0 = 사용 안 함(기본). 정하면 격리한 지 그 일수가 지난 폴더만 자동으로 지웁니다(표식 없는·진행 중 폴더는 그대로).

절차 연결 승인 

    
'이 판정 전용' 연결 중 판정 제목 낱말이 절차에 없어 감사에 걸렸다가 에이전트가 검토해 맞다고 적은 것입니다(검토 ≠ 승인).
      여기서 승인하거나 반려합니다. 반려한 연결은 다시 '적합성 낮음' 대기열로 돌아가 지식 출시가 멈춥니다(고쳐야 나갑니다).
      위험도 = 그 절차 2차 명령에 세션 종료·삭제·중지·설정 변경 같은 되돌리기 어려운 동작이 몇 종류 있나 — 높은 것부터 보십시오.
      한 건 승인은 상세를 연 뒤에만 됩니다. 묶음 승인은 서버가 고른 표본 3건을 열어 본 뒤에만 되고, 결과는 '승인'이 아니라 '묶음 승인'(개별 검토 아님)으로 따로 셉니다.
      위험 명령·제품 불일치·미확인 표시·치명 판정이 걸린 연결은 묶음에 넣을 수 없습니다(한 건씩).
      결정은 data/link_approvals.jsonl 에 이력으로 남고 감사 기록에도 남습니다.
