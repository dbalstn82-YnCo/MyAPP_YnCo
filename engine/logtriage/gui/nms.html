이 장비는 자원 사용률을 수집하지 않습니다(가용성만) — 아래에서 수집 방식을 고르면 바로 CPU·메모리·디스크·네트워크를 봅니다.
장비를 고르면 그 장비의 장애·복구 기록을 봅니다.
장애와 복구 이력 전체 장비 · 최근 200건

상태는 등록한 ICMP·TCP 검사 결과이며 장비의 모든 기능을 보장하지 않습니다. 기본 설정은 30초 간격 검사, 3회 연속 실패 시 장애, 2회 연속 성공 시 복구입니다(항목마다 바꿀 수 있음). 알림 팝업은 이 화면을 열어 둔 브라우저에서만 표시됩니다.

감시 항목 등록

같은 장비도 ICMP 와 서비스 포트를 각각 등록할 수 있습니다. 호스트명·IPv6 zone ID 는 지원하지 않습니다.

에이전트는 이 주기를 응답으로 받아 다음 전송부터 따릅니다(Python 에이전트). SNMP 는 장비 부하를 생각해 10초보다 짧게 하지 않습니다.
계정별 프로세스 수·CPU·메모리와 상위 프로세스 이름(명령행 인자 없음). Linux 는 /proc·ps 로 전 계정, Windows 는 관리자 권한이 아니면 다른 계정은 N/A. SNMP 장비는 해당 없음.
에이전트 설치 — 모니터링 대상 서버에서 실행하면 30초마다 사용률을 이 서버로 보냅니다. 위 IP 와 같은 주소(또는 같은 호스트명)에서 보낸 값만 저장됩니다.
간편 설치 (권장) — 대상 서버에서 명령 한 줄
등록 코드는 30분 · 1회용이고 이 서버에만 쓸 수 있습니다. 수집 토큰은 화면·명령줄·셸 기록에 나오지 않고 설치 파일(권한 600)에만 들어갑니다. root(sudo)로 실행하면 전용 계정으로 도는 시스템 서비스, sudo 없이 실행하면 그 계정 사용자 설치입니다(Linux·AIX·HP-UX·Solaris). 

            
이 서버는 http 입니다 — 등록 코드와 수집 토큰이 평문으로 오갑니다(30초마다 보내는 수집값도 같음). 사내망 밖을 지나면 LogTriage 를 https 로 운영하십시오(https 를 강제한 서버는 등록도 https 로만 받습니다).
